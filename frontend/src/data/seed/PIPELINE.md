# 样例数据链路：种子定义 → 播种 → 持久化 → 重置

本文说明延误事件（以及其余 17 个同构模块）样例数据的工程化链路。链路分为四段，每段只有一个
归属文件，改动任何一段都不用去逐条改样例。

## 1. 种子定义（管"种什么"）

- 文件：`src/data/seed/types.ts`（类型）、`src/data/seed/definitions.ts`（定义本体）。
- 种子定义只描述**每个模块长什么样**，不直接写展开后的行：
  - 字段清单、状态清单来自 `src/data/modules.ts` 的 `ModuleMeta`，种子定义不再复制一遍；
  - 每个模块只配：编号前缀、样例数量（默认=状态数，保证每个状态都有一条）、每条样例的
    覆写值（默认只需写业务上各不相同的字段，其余按字段名类型推导）。
- 推导规则集中在 `src/data/seed/builder.ts`：
  - 编号类字段（名称以「编号 / 单号」结尾）→ `前缀-序号`；
  - 数字类字段（影响旅客数、件数、用量……）→ 按序号给出数量级合理的数值；
  - 日期类字段（名称含「时间 / 日期 / 时段」）→ 相对当前日期回填，保证「今日 / 本月」
    这类统计维度在任何一天都有数据；同一行的成对日期取同一天；
  - 其余文本字段 → `<模块名>样例<序号>`。
  - `status` 依次取状态清单中的一个状态；`pending = status !== 末状态`（末状态是终态）；
    `abnormal` 固定落在第二条样例上，看板始终有一条异常演示。
- 字段改名、增删字段、状态清单变长变短：只动 `modules.ts`，重建后样例自动跟随；
  新增统计维度（metrics）只影响统计函数，不新增样例行，不需要再造一批。
- 定义装入引擎前先过 `validateSeedDefinition`：模块 key 必须存在、状态必须在状态清单内、
  覆写字段必须在字段清单内、前缀不能为空。校验不过 = 取不到合法种子定义，按失败处理。

## 2. 播种时机（管"什么时候种、怎么种得稳"）

- 文件：`src/data/seed/source.ts`（取定义）、`src/data/seed/engine.ts`（重建引擎）、
  `src/data/seed/index.ts`（门面 + 应用启动接线）。
- 应用 `main.ts` 在挂载前 `await seedOnStartup()`：
  1. 取种子定义：默认取仓库内定义；`VITE_SEED_URL` 配置了远端地址时 fetch 远端定义。
     远端取不到 / 校验不过 → 整个播种按**失败**处理，**不静默回退**（否则配了远端却悄悄
     用了另一份数据，难以排查）；错误抛出到状态里，页面出现「重试播种」入口。
  2. 逐模块、分批写入。批次为幂等提交，每提交一批就在种子状态里记录 `nextIndex`
     （断点）；中断后重跑从断点那一批接着补，不从头再来。
  3. 全部完成后写入定义哈希与 `doneAt`。再次启动哈希不变即跳过，重复执行不产生重复记录、
     不产生重复编号。定义改了（哈希变了）自动重新对账：仍按业务编号幂等 upsert，
     新定义里新增的样例补进去，已有的不动。
- 同一模块的播种过程在内存里加锁去重，并发调用复用同一个 Promise。
- 重置入口（见第 4 节）是显式触发的同一条重建管线，只是先清空本模块再种。

## 3. 持久化层（管"种在哪、互不影响"）

- 文件：`src/data/local-store.ts`。
- 每个模块一个 localStorage 键：`airport-ground-ops:entries:<模块key>`；种子状态单独放
  `airport-ground-ops:seed-state`。重置或播种某模块只写这一个键，**别的模块的本地记录物理
  上不受影响**。
- 首次读到旧版单键（`airport-ground-ops:entries`）时做一次性拆分迁移：把每个模块拆到各自
  的键，用户已有记录原样保留；旧键保留不删（迁移只读它），迁移只执行一次。
- 编号由持久化层按模块分配：种子样例从 1 起稳定编号；真实新增接着最大号往后排。
  幂等以业务编号（事件编号等）为准，不靠行 id。
- 读写接口保持 `listRows/saveRows/resetRows/allRows` 不变，上层 `local-service.ts` 无感。

## 4. 重置入口（管"只重置这一个模块"）

- `resetModule(key)` 只清第 3 节里该模块自己的键，然后只对该模块跑一次种子重建，
  并清掉该模块的播种断点。其他模块的键和状态一律不碰。
- 入口 UI 在各模块页面页头新增「重置示例数据」按钮（确认后执行）；18 个模块页面结构完全
  同构，收敛为 `src/views/ModulePage.vue` 一个通用组件，由路由注入模块 key，以后字段/状态
  变化连页面都不用改。
- 种子失败时页面页脚展示失败原因和「重试播种」按钮，重试只重跑未完成的批次。

## 5. 冲突与回填裁决

- **种子定义与本地已有数据冲突时：本地真实记录优先，种子只补缺。**
  依据：种子是演示数据，localStorage 里的是用户操作产生的真实记录；样例可以随时重建，
  真实记录被静默覆盖不可恢复。因此引擎对业务编号已存在的行一律 skip/upsert（字段值以本地
  为准），绝不删除或改写用户行；定义里新增的样例才追加。
- **不按上报时间回填或改写存量行的字段。**上报时间只用于新补样例的展示排序与「今日/本月」
  统计；拿样例定义去倒灌存量字段会把真实记录改坏。需要全新样例时走模块重置（重置语义本来
  就是"放弃本模块演示数据、回到种子"，且只影响这一个模块）。
- 模块内展示顺序：有日期字段的按首个日期字段升序（即按上报时间排），没有的按业务编号排；
  排序只影响展示，不动行身份。

## 6. 可测试性与构建

- `src/data/seed/__tests__/` 下用 vitest 覆盖：构建确定性、字段/状态跟随、幂等、
  断点续跑、失败重试、重置隔离、v1 迁移、指标计算。存储以可注入的 KV 接口测试，
  不依赖浏览器。
- `npm run dev`（开发）与 `npm run build`（生产，含 vue-tsc 类型检查）都必须通过，
  另提供 `npm test`。
